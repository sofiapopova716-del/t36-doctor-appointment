== Требования

=== Бизнес-требования
[cols="1,4",options="header"]
|===
| ID | Формулировка
| BR-01 | Сократить долю пациентов, которые уходят без записи из-за перегруженной регистратуры, и убрать очередь, вызванную поиском свободного времени вручную.
| BR-02 | Снизить количество неявок пациентов на приём за счёт подтверждения записи, чтобы врачи не простаивали.
| BR-03 | Сократить время ожидания пациента в регистратуре при записи, чтобы снизить количество жалоб.
|===

=== Пользовательские требования
[cols="1,4",options="header"]
|===
| ID | Формулировка
| UR-01 | Пациент должен по ссылке или через систему увидеть свободные слоты к нужному врачу и записаться на удобное время.
| UR-02 | Пациент должен иметь возможность отменить запись без звонка в регистратуру.
| UR-03 | Пациент должен получить напоминание о приёме за день до визита.
|===

=== Функциональные требования
[cols="1,4",options="header"]
|===
| ID | Формулировка
| FR-01 | Система должна перевести запись в статус «подтверждён» только если пациент подтвердил её за день до приёма. Если подтверждения нет — система автоматически отменяет запись и освобождает слот.
| FR-02 | Система должна отображать только свободные слоты врача на выбранную дату.
| FR-03 | Система должна запрещать запись к узкому специалисту без направления от терапевта.
|===

=== Бизнес-правила
[cols="1,4",options="header"]
|===
| ID | Формулировка
| BP-01 | Запись на приём к узкому специалисту возможна только при наличии направления от терапевта.
| BP-02 | Запись без подтверждения за день до приёма подлежит автоматической отмене и освобождению слота.
| BP-03 | Срок хранения записи задаёт регламент поликлиники; по его истечении запись аннулируется, а слот возвращается в расписание.
|===

=== Нефункциональные требования
[cols="1,4",options="header"]
|===
| ID | Формулировка
| NFR-01 | Поиск свободных слотов по врачу и дате — не позднее 3 секунд в 95 % обращений при нагрузке до 50 запросов в минуту.
| NFR-02 | Система должна выдерживать не менее 50 одновременных активных пользователей без потери данных.
| NFR-03 | Данные о записи должны сохраняться при сбое и восстанавливаться не позднее чем через 5 минут.
|===

=== Ограничения
[cols="1,4",options="header"]
|===
| ID | Формулировка
| C-01 | Помещение поликлиники старое: нельзя устанавливать терминал, перепланировать холл, покупать дорогие решения. Бюджет ограничен. Источник расписания — действующий контур МИС.
| C-02 | Часть пациентов — пожилые люди: нужен простой интерфейс (крупные кнопки, простая навигация) и альтернатива по телефону.
|===
